# Gateway VPN — модель безопасности реализации

- Любой boot начинается с `PATH_BLOCKED`; management API не открывает direct LAN path.
- Основной `gateway-vpn.service` не имеет `CAP_NET_ADMIN` и получает только `CAP_NET_RAW` для `SO_BINDTODEVICE`/`SO_MARK` служебных modem-bound DNS/HTTPS sockets. Root broker ограничен `CAP_NET_ADMIN` и `CAP_NET_RAW`, необходимыми для owned routes/nft/WireGuard и modem-bound endpoint DNS; nftables и Mihomo вынесены в отдельные units с собственными минимальными capability sets.
- Пароли хешируются Argon2id (`m=65536 KiB, t=3, p=2` по умолчанию). Session и CSRF tokens хранятся только как SHA-256 digests.
- Browser cookie: `Secure`, `HttpOnly`, `SameSite=Strict`; state-changing API требует session-bound CSRF token.
- Login failures сохраняются и получают progressive delay. Сессии отзываются в SQLite.
- Одноразовый bootstrap-пароль блокирует весь API, кроме session/password/logout, пока пользователь не задаст новый пароль. Смена собственного пароля сохраняет только текущую сессию; administrative reset и disable отзывают все сессии target user.
- Все локальные пользователи MVP являются администраторами без ролей. Username имеет консервативный ASCII-format и case-insensitive unique index; текущего/последнего enabled пользователя отключить нельзя, а удаление разрешено только после disable и отдельного confirmation header.
- API показывает только SHA-256 session ID, username и timestamps; bearer cookie, CSRF digest и client-key digest не возвращаются. Спецификация `docs/openapi.yaml` contract-tested против каждого реально зарегистрированного `/api/v1` method.
- API использует явные redacted DTO. Subscription secret refs, URLs/tokens, modem identity hash, serial и private keys не возвращаются.
- Config loader запрещает symlink, duplicate/unknown YAML fields, multi-document input и небезопасные permissions.
- TLS private key, bootstrap password и dynamic secrets создаются atomic write + fsync с mode `0600`.
- Mihomo controller доступен только на loopback и требует secret; полная subscription config не исполняется, разрешённые proxy fields проходят sanitizer.
- Content probes используют отдельный mixed listener только на numeric loopback и отдельные `probe-path-*` selectors; controlled select и HTTPS request сериализованы. Active data-path group для проверки тела не переключается.
- Policy mutation сохраняет текущий node в provider только на durable 120-секундный grace. Он не считается candidate без свежего результата новой generation; crash/restart очищает transition в `PATH_BLOCKED` до обычной convergence.
- nftables controller владеет только `table inet gateway_vpn`, выполняет `nft --check` и никогда не вызывает `flush ruleset`.
- Независимый root firewall guard имеет только `CAP_NET_ADMIN`: при потере schema generation/drop markers он сначала administratively отключает transit LAN, сохраняет root-only quarantine marker, восстанавливает только owned table в `PATH_BLOCKED` и возвращает link up после повторной проверки. Старый active TUN generation не восстанавливается без control-plane re-verification.
- Signed release требует строгие metadata, Ed25519 signature доверенным key, signer fingerprint, полный manifest и SHA-256 каждого файла; archive parser ограничивает gzip member/footer/padding, entries/path/depth/bytes и запрещает links/devices/trailing data. Штатный production secret — portable `.gvkey`: Argon2id 64 MiB/3/p2 + AES-256-GCM с authenticated fixed header, bounded strict payload, private→public/fingerprint self-verification, exclusive create/fsync и byte-identical verified backup в другом destination. `.gvkey` и passphrase хранятся раздельно; passphrase не принимается через argv/environment. Signing остаётся Linux-only: encrypted wrapper раскрывает PEM только в проверенный `/dev/shm` tmpfs `0700`, обычный use-time custody contract повторно проверяет pair, а trap удаляет plaintext при любом завершении. Постоянный plaintext key workflow остаётся только compatibility/test contract и требует encrypted filesystem. Bundle до дорогой сборки отвергает mismatched pair; staging не исполняет candidate и не меняет live state.
- Первый install не доверяет verifier из candidate archive. Отдельный `gateway-vpn-bootstrap` заранее закрепляется внешним SHA-256; generated command использует HTTPS-only `curl` с fallback на GNU `wget`, проверяет hash и лишь затем вызывает bootstrap напрямую из root-shell либо через `sudo`. Bootstrap затем независимо закрепляет raw channel manifest SHA-256, exact channel/version/source commit и Ed25519 public-key fingerprint, проверяет detached channel signature, role filename/hash/size и полный signed release tree до запуска role installer.
- Caller-supplied bootstrap URL запрещает credentials, fragment, query, literal IP и нестандартный HTTPS port. Короткоживущий signed query допускается только после HTTP redirect и только для allowlisted `objects.githubusercontent.com`/`release-assets.githubusercontent.com`; content всё равно обязан совпасть с закреплённым hash/size/signature. Redirect на иной origin или query на `github.com` отклоняется.
- Channel artifacts имеют точные role filenames (`gateway`, `vps`, `deploy`, `bootstrap`) для exact version/Linux/amd64. Trusted channel builder требует clean committed source, подписывает sorted unique role records, тут же проверяет их public key и генерирует immutable GitHub tag command; `latest`, `curl | shell` и доверие одному TLS origin не являются частью install contract.
- `gateway-vpn-deploy` до исполнения сверяется с externally pinned SHA-256, затем проверяет собственные size/hash/version/commit по signed channel. OpenSSH запускается только как fixed `/usr/bin/ssh` на Linux либо `C:\Windows\System32\OpenSSH\ssh.exe` на Windows, с отключённым user config/agent/password/keyboard-interactive/TTY, строгим pinned `known_hosts`, bounded stdout/stderr и validated destination/port/path inputs; обе role dry-run фазы завершаются до первого apply. Linux использует private ControlMaster, а Windows — один long-lived `ssh.exe`/TCP на host с bounded framed Bash broker, поскольку Win32 Client ControlMaster не поддерживается; в обоих случаях после fail-closed apply не требуется новый SSH connection.
- Gateway private key создаёт локальный helper от service UID, VPS private key — signed VPS installer после full preflight, admin private key — optional local deploy lifecycle. Через SSH/argv/report передаются только public keys; pending keys имеют mode `0600`, directory `0700`, переживают interruption для idempotent resume и удаляются только после atomic config write + directory fsync. Existing config принимается лишь при exact peer/endpoint contract и молча не ротируется.
- Management Fabric применяет default deny отдельно к каждому `Gateway × VPS` link: собственные keypair/interface/subnet/generation, одновременно active links без общего wildcard peer, запрет Gateway↔Gateway/admin↔admin и запрет management→Internet. Pairing/rotation передаёт только public identity и одноразовое bounded proof; VPS login/password, private key либо произвольная SSH-команда не являются частью Gateway Web/API contract. Signed VPS installer выдаёт bounded invitation с pinned VPS fingerprint/expiry; Gateway WebUI импортирует код/файл, а любой pre-pairing listener принимает только этот протокол и закрывается после success/expiry. После pairing Agent API слушает только localhost/admin WireGuard.
- Публикация локального ресурса default-off и требует совпадающих versioned ACL на Gateway и VPS. Для каждой пары `site × resource × VPS link` выделяется collision-checked alias prefix; произвольные user-supplied routes/NAT/nft expressions в privileged boundary не передаются. Одинаковые домашние RFC1918-подсети не получают общий ambiguous `AllowedIPs`.
- Рекомендуемый административный режим `END_TO_END_RELAY` завершает inner `wg-admin` на Gateway: VPS знает только allowlisted relay tuple и способен отказать в доставке, но не имеет inner private key и не может расшифровать либо сгенерировать authenticated admin packet. `ROUTED_HUB` явно помечается более доверительным opt-in и не является silent fallback при ошибке end-to-end contour.
- VPS Agent является одним bounded Go service с embedded WebUI/CLI/SQLite; его root boundary принимает только typed Gateway VPN operations и fixed owned units. Watchdog не перезапускает AmneziaVPN/Docker/UFW/foreign WireGuard, не управляет host power и не исправляет общий OS state. VPS firewall использует scope-only accept/deny для owned interfaces/addresses/ports и не создаёт blanket drop, способный заблокировать чужой VPN; install/update/uninstall проверяют неизменность foreign routes/rules/services отдельным coexistence gate.
- Gateway dependency provisioning также является opt-in и использует фиксированный allowlist `iproute2/nftables/wireguard-tools/kmod/procps/dnsmasq-base` плюс `openssh-server` только при default-on либо явно выбранном SSH/SFTP management, двойную APT simulation с `--no-remove --no-upgrade` и повторный full host preflight. При SSH opt-out пакет/service не меняются и TCP/22 rule отсутствует. При включении existing `sshd_config`, users, keys и password policy сохраняются; installer требует успешный `sshd -t`, enabled/active `ssh.service` и IPv4 wildcard listener, но owned firewall разрешает TCP/22 ровно через `gateway-vpn-lan`, никогда через Ethernet uplink/HiLink. Используется binary-only `dnsmasq-base`, а отдельный DHCP/DNS process работает как `gateway-vpn-dns:gateway-vpn` и пишет lease только в systemd-owned `/var/lib/gateway-vpn-dnsmasq` mode `0700`, вне закрытого application state root. LAN принимается только как private usable `/16../30`; bounded typed `ip -json` проверка отклоняет пересечение с WireGuard management, любым другим host address network или non-default route до application mutation.
- Gateway first-install transaction создаёт durable root-only marker до host mutation и загружает signed owned `PATH_BLOCKED` ruleset до назначения LAN/включения `net.ipv4.ip_forward`. Прежние forwarding/IPv6/link/address значения восстанавливаются owned recovery; systemd application units при active или broken marker требуют отдельный ephemeral `root:root 0600` `/run/gateway-vpn-install-authorized`, который существует только внутри живого installer и исчезает при reboot.
- Root self-health supervisor имеет только fixed signed component/action/path surface и capability set `CAP_NET_ADMIN/CAP_SYS_BOOT/CAP_DAC_READ_SEARCH`; SQLite policy читается новым query-only handle, а restart/reboot budget атомарно сохраняется и fsync-ится до действия. Per-component policy выбирает только `MONITOR_ONLY`, `RECONCILE` или `RESTART` из code-defined allowlist. Read-only checks покрывают control heartbeat/workers, SQLite, owned firewall, broker/networkd/DNS/SSH/Mihomo, оба WireGuard contour, policy routing, desired/observed convergence, verified backup/WAL, resources и logging/export pipeline. WireGuard interface/address/peer/fwmark и owned protocol-186 routes проверяются отдельно от handshake; stale handshake относится к external outage. Любая recovery сначала применяет `PATH_BLOCKED`; external outage и resource pressure не restart/reboot-eligible, host reboot default-off, maintenance suppresses actions. `NotifyAccess=all` ограничен собственным systemd service cgroup и нужен для heartbeats из Go runtime threads; произвольные child executables/commands отсутствуют. Control `Requires/PartOf` supervisor, а runtime directory сохраняется через restart, поэтому потеря supervisor не оставляет живой control с невидимым stale heartbeat mount. UID-bound root broker также имеет `CAP_SYS_BOOT` только для typed manual power API: `REBOOT`, `SHUTDOWN` и hardware-verified `RTC_POWER_CYCLE`; command/unit/path из HTTP не принимаются.
- VPS dependency provisioning включается только явным `--install-dependencies --apply`. Installer не меняет APT sources, формирует фиксированный allowlist `iproute2/nftables/wireguard-tools/kmod/procps/python3`, до установки запускает `apt-get -s install --no-install-recommends --no-remove --no-upgrade`, запрещает любой `Remv` и любую upgrade action, после `apt-get update` повторяет simulation и не выполняет `upgrade`, `full-upgrade`, `dist-upgrade` или `autoremove`. Полный пакет `python3` обязателен: `python3-minimal` не гарантирует стандартный JSON-модуль, используемый строгими host gates. Ошибка simulation может быть классифицирована как требующая refresh только отдельным exit code `10`; bootstrap разрешает его исключительно в read-only фазе apply-транзакции, тогда как removal/upgrade/empty plan остаются фатальными. Ubuntu 20.04 до любой managed package mutation требует уже установленные `ubuntu-advantage-tools`/`python3`, активные Pro + `esm-infra` + `esm-apps` и отсутствие pending updates; после refresh проверка повторяется до package install. После package install весь host/nft/WireGuard/port/conflict preflight выполняется заново до создания VPS private key или managed application state.
- OS packages являются состоянием хоста и намеренно не удаляются application rollback/uninstall: автоматический откат пакетов после успешного `dpkg` мог бы удалить разделяемые зависимости других сервисов. Незавершённая Gateway VPN transaction восстанавливает только owned files, sysctl, systemd, WireGuard interface/config и `inet gateway_vpn_vps` table; WireGuard keys сохраняются, если оператор отдельно не запросил purge.
- Gateway WebUI uninstall использует password re-auth, CSRF, четыре явных acknowledgement и точную русскую фразу. Через privilege boundary проходит только validated `uninstall-[a-f0-9]{32} + PRESERVE_DATA|PURGE_DATA`; command/path/unit/package selector не принимаются. Root broker fsync-публикует exclusive marker и запускает один fixed unit. Guardian до mutation проверяет signed release, сохраняет hash-bound root-only tooling вне application tree и переводит forwarding в `PATH_BLOCKED`; active marker удаляется только после fsync terminal receipt. Purge не создаёт скрытую копию удалённой DB, а Ubuntu packages намеренно остаются.
- VPS install/recovery/uninstall сериализованы одним root-owned mode `0600` `flock` в `/run/lock`. Lock path создаётся с `noclobber`, symlink и чужой owner/mode отклоняются. Active transaction и orphan temp/pointer artifacts проверяются до package mutation. Recovery не архивирует active marker, пока owned nft/systemd/sysctl/filesystem cleanup и повторная проверка forwarding не завершились; при любой ошибке marker остаётся для следующего boot/manual retry.
- Root update повторно проверяет signed staging, запускает candidate offline check только после verification, мигрирует копию DB и переключает согласованную пару SQLite+`current`. Pointer-only update требует совпадения вычисленного signed `host_contract_sha256` для всего packaged systemd lifecycle; изменённые root-owned units не игнорируются, а отклоняются до mutation. Независимый `recovery` symlink остаётся на старом release весь 24-часовой health window и переводится на новый только после повторной health/DB проверки и finalization; root-owned redundant journals/snapshots, inter-process `flock`, boot recovery и `OnFailure` resume обеспечивают fail-closed rollback. Recovery unit запускает bounded journal scan даже при потере `active.json`, потому что process мог погибнуть между записью transaction-local copy и active pointer; отсутствие transaction является безопасным no-op, повреждение обеих копий блокирует Agent вместо догадки. Ephemeral `/run/gateway-vpn-vps-update-live` подавляет этот scan только при живом apply/finalize и не переживает reboot. Та же версия не может обозначать другой signed artifact.
- Изменившийся host contract обновляется только отдельной signed installer transaction. Fresh install и внешний download/bootstrap требуют NTP; уже установленный fail-closed Gateway может проверять заранее полученный release офлайн без NTP/DNS, поскольку installer сначала проверяет полный manifest, подпись и embedded version нового release, а transaction до mutation независимо проверяет подпись старого release, exact DB и host state. Candidate verifier отдельно требует exact gap-free migration prefix. После quiesce nested installer принимает отсутствие NTP/DNS только при унаследованном exact FD9 lock и строгом root-owned `APPLYING` marker этой версии, но повторяет все локальные resources/APT/kernel/network invariants. Затем создаётся cold root-only snapshot старого release/DB/config/secrets и fixed Gateway-owned host projection; synthetic snapshot parents запрещено накладывать на host root. Boot recovery запускается из отдельного `/usr/libexec`, восстанавливает только allowlisted destinations, повторно проверяет старую подпись/binary/DB и не отзывает active marker до успешной постановки старых service jobs. Recovery guardian unit/helper исключены из destructive restore и остаются enabled при повторной ошибке rollback; прежнее состояние guardian восстанавливается только после durable terminal receipt. Необязательный GRUB projection не блокирует mount namespace recovery unit на хостах без `/boot/grub`. Для exact удаления и восстановления owned root directories namespace открывает их родители `/opt`, `/var/lib` и `/var/log`; helper остаётся fixed, signed, без пользовательских параметров и начинает mutation только после строгой проверки marker/snapshot. Nested install/recovery наследует внешний `flock` и не может освободить его либо удалить внешний helper. Merged completion marker сохраняет известные исходные до первой установки OS states; отсутствующее в legacy marker состояние `ssh.socket` не выводится из post-install host и остаётся неизменяемым будущим uninstall.
- Web/API получает root update outcome только безаргументным broker request и видит path-free DTO: versions/state/timestamps/error code. Release paths, snapshot ID, DB hash и systemd output не пересекают privilege boundary.
- Все application records проходят key/value/nested-error redaction до JSON handler и journald. Permanent debug запрещён bootstrap config: временный component-scoped debug имеет durable deadline 5 минут–24 часа, а `auth_audit` нельзя снизить ниже `info`. Gateway VPN services используют отдельный bounded journal namespace; payloads, response bodies, credentials и modem identity не являются debug data.
- Retention меняется только parameter-free broker request: root перечитывает desired policy из SQLite, пишет один фиксированный journald drop-in, проверяет fixed namespace unit и откатывает прежний файл при failure. HTTP не передаёт root ни путь, ни unit, ни retention values.
- Control plane не получает членство в широкой группе чтения system journal. Технический журнал выдаёт root broker только из namespace `gateway-vpn` через фиксированный `/usr/bin/journalctl`; allowlisted filters, page/time/cursor bounds, subprocess limit 2 MiB, broker response limit 64 KiB, session rate limit и второй redaction pass ограничивают поверхность чтения.
- Тематические log tabs являются allowlisted projections того же journald stream. SFTP exporter повторно redacts данные, ограничивает input/line/file/archive/total bytes, пишет atomic regular files `0640` только в проверенный root-owned tree `/var/log/gateway-vpn`. Группа `gateway-vpn-log-readers` получает read-only directory traversal; application UID, WebUI user и отдельный SFTP daemon не получают новых широких прав.
- `wg-ingress` отделён от `wg-mgmt`. Server/managed-peer private keys и PSK находятся только в root-only regular files под `/var/lib/gateway-vpn/secrets/wireguard-ingress`; SQLite хранит public/runtime/policy metadata. Managed `.conf`/QR требует password re-auth и single-use 90-second session-bound grant, возвращается с `Cache-Control: no-store`; external peer никогда не раскрывает private key. Duplicate key/address/subnet/behind-route отклоняются до apply, listener interfaces входят в fixed firewall set, а любая ошибка convergence удаляет interface fail-closed.
- Diagnostic bundle создаётся только в памяти как fixed-entry ZIP (24 MiB uncompressed/32 MiB archive) с per-file SHA-256 manifest. Parameter-free root collector запускает только фиксированные absolute `uname/ip/nft/wg/mihomo` команды, читает `/etc/os-release`, выбирает owned routing/nft state и возвращает не более 60 KiB; HTTP не передаёт command/path/interface/table или `include_secrets`. Host, event и journal данные повторно sanitizes/redacts перед ZIP, WireGuard keys/endpoint host, MAC/modem identity, subscription payloads/URLs, proxy configs/credentials и target bodies исключены.
- Endurance harness работает только на Linux, требует TLS 1.3 + explicit CA и не использует redirect или environment/argv password. Credential file обязан быть single-link mode `0600`; cookie/CSRF и password остаются только в памяти, session отзывается при exit. Samples и verified start/end diagnostics пишутся `0600` в новый `0700` directory. Smoke не может выдать endurance PASS; developer/release нельзя сократить, они требуют clean VCS-stamped harness и versioned Gateway, а release дополнительно требует explicit hardware attestation.
- Portable backup никогда не записывает plaintext ZIP на постоянный storage: `.gvpn` использует Argon2id и chunked AES-256-GCM с authenticated header, monotonically indexed chunks и обязательным authenticated final record. Password re-authenticated WebUI передаёт passphrase только по mode-0600 UID-bound Unix socket; root broker создаёт transient verified SQLite snapshot и читает fixed config/state trees, включая недоступные application UID root-owned Management Fabric/`wg-ingress` keys. Root staging находится в `/var/lib/gateway-vpn-privileged/backup-exports` `0700`; обратно пересылаются только path-free metadata и encrypted bytes, которые control plane повторно проверяет по length/SHA-256. Passphrase отсутствует в argv/environment/SQLite/trigger/journal. Restore повторно ограничивает file count/bytes, отклоняет traversal, duplicate, symlink и неизвестные paths, требует DB/config/Mihomo API secret/TLS cert+key, а при настроенном `wg-ingress` — server/managed-peer keys и PSK; passphrase/upload после staging не сохраняются.
- VPS Hub использует отдельный authenticated role format `.gvpn-vps` с тем же bounded Argon2id/AES-256-GCM envelope; cross-role restore отклоняется до extraction. Он содержит только VPS-owned Agent DB/config/TLS/keys/peers/prefix/ACL/update state и исключает Gateway DB/private keys, sessions/logs/diagnostics и ephemeral/used pairing invitations. Same-VPS restore требует explicit replacement/quarantine, import-as-new всегда генерирует новые `vps_id`/keys/prefixes/pairing; оба режима остаются default-deny до fresh reconciliation.
- Unprivileged staging не получает права менять live-файлы и создаёт только mode-0600 trigger внутри собственного Agent state; systemd `.path` активирует fixed parameter-free root unit. Root apply повторно хеширует manifest tree, проверяет SQLite/config, создаёт `pre-restore` snapshot и использует только фиксированный destination set. Для `IMPORT_AS_NEW` он также атомарно заменяет только `/etc/wireguard/wg-mgmt.conf` новым key/no-stale-peer contract. Candidates создаются рядом с destinations, а root-owned journal/rollback paths позволяют восстановить прежний набор после partial apply или power loss.
- VPS Hub pairing хранит только SHA-256 случайного 256-bit token; raw bundle выдаётся один раз и очищается WebUI при смене страницы. Expiry ограничен 5 минутами–24 часами, неверные consume используют durable budget 8, а prefix reservation/peer/invitation/fabric generation меняются одной SQLite transaction. Replay, reused VPS/Gateway/admin public key, duplicate site/address и overlap active либо released prefix отклоняются до host mutation. Public completion endpoint не принимает credentials/private keys, не обходит firewall bind и до отдельного pre-pairing profile недоступен из Internet.
- VPS control API принимает только typed Gateway/admin/resource/ACL fields: canonical private IPv4, `/30` link, `/32` admin, fixed resource/access-profile/protocol enums и bounded ports. `LOCAL_SUBNET` требует acknowledgement; resource alias не пересекает ни одну allocation. Peer revoke требует password re-authentication и точную фразу, удаляет grants/закрывает публикации до ответа. До root apply API публикует `host_apply_available=false`; ownership-only controller health никогда не restart/reload AmneziaVPN, Docker, UFW, чужой WireGuard либо VPS host.
- Managed administrator key создаётся только внутри Agent-owned `0700` tree как atomic `0600` file; SQLite/API/list/audit содержат public key, secret reference/lifecycle metadata без private material. Одноразовая `.conf` выдача требует CSRF, password re-authentication и exact per-peer phrase, атомарно переводит grant `AVAILABLE → CONSUMED`, удаляет secret до HTTP response и запрещает concurrent/repeated download. Ошибка удаления переводит lifecycle в `CLEANUP_REQUIRED` без выдачи содержимого; startup cleanup не возвращает grant в `AVAILABLE`. Rotation создаёт второй peer/address и оставляет прежний активным до отдельного revoke. Portable backup включает только `AVAILABLE` refs, исключая consumed/revoked/orphan files; `IMPORT_AS_NEW` удаляет весь source administrator secret tree.
- VPS host-plan является детерминированной typed проекцией schema generation: фиксированные `wg-mgmt`, UDP/51821 и route protocol `186`, только canonical private interface addresses, `/32` peer sources, опубликованные alias routes и bounded TCP/UDP/ICMP ACL. В нём отсутствуют private refs/keys, command/executable/path и `0.0.0.0/0`; до отдельной root transaction эта read-only проекция не считается applied host state.
- Restore отзывает все sessions, очищает login attempts, удаляет stale Mihomo active link и принудительно сохраняет `PATH_BLOCKED`; backup evidence никогда не считается свежей path qualification. Resume unit возвращает только management/control, а data plane появляется после обычного reconciliation.
- Bootstrap config фиксирует executable `/opt/gateway-vpn/current/libexec/mihomo` и Mihomo API secret/TLS paths внутри managed state directory. Root diagnostics также использует compile-time fixed Mihomo path; восстановленный YAML не является источником root executable/path.

Root-доступ находится вне threat model. Firewall guard защищает от сбоя/конфликтующего сервиса/административной ошибки, но не от намеренного root attacker.
## Привилегированное изменение сети

Web/API работает как `gateway-vpn` только с `CAP_NET_RAW`; capability не позволяет менять routes/nftables. Привилегированные изменения, ограниченное чтение namespaced journal, parameter-free host diagnostics, restore/update trigger и sanitized update-status read выполняет отдельный root broker через Unix socket owner `gateway-vpn`, mode `0600`; после accept дополнительно проверяется Linux `SO_PEERCRED` UID. Broker принимает strict bounded JSON, typed LAN candidate, parameter-free routing/WireGuard/logging/diagnostics/restore/update operations, bounded journal query, subscription bootstrap tuple, direct-probe tuple с существующими modem/target ID, protected Mihomo version IDs и modem-recovery tuple `uplink_id + enum action + policy_generation` — не shell command, executable path, restore/update id/path/unit, destination file, произвольный interface/sysfs path/table, journald unit/namespace или `journalctl` argument. Для recovery root повторно сверяет active durable attempt, HiLink type/enabled state, generation и текущий interface из SQLite; текущий hardware profile исполняет только фиксированный `/usr/bin/networkctl renew <derived-ifname>`, а firmware/USB actions остаются `HARDWARE_ACTION_NOT_AVAILABLE` до отдельного identity-safe gate.

`output` остаётся policy drop. Служебные DNS/HTTPS разрешаются только для UID процесса и tuples `interface × fwmark × IPv4 × port`; direct-probe root повторно получает authoritative modem tuple и текущую HTTPS target policy из SQLite, принимает не более 16 public IPv4 и выдаёт временное разрешение на 2 минуты. Mihomo endpoint IP root получает из immutable protected payloads и разрешает отдельно через каждый `MODEM_READY`.

WireGuard private key принимается только authenticated HTTPS + CSRF update, атомарно сохраняется в `secrets/wireguard.yaml` с mode `0600` и никогда не возвращается Web API. Между control plane и root broker передаётся только пустой `sync` request: endpoint, keys, modem ID, interface, route table и fwmark root повторно получает из protected config и SQLite. nftables разрешает только текущий tuple `interface × fwmark × public endpoint IPv4 × UDP/51821`.

Transaction directory принадлежит `root:root` и имеет mode `0700`. Rollback manifest содержит только interface/CIDR/local management URLs, проверяется по schema и SHA-256. Перед privileged action broker сверяет manifest с SQLite, текущим strict config и реальными `ip -json address` данными. Snapshot/restore ограничен фиксированными Gateway VPN config, dnsmasq, persistent systemd-networkd LAN policy и owned nftables table; apply/rollback вызывает только `networkctl reload`, а старый адрес остаётся до explicit confirmation.

Restore использует отдельный root-owned `/var/lib/gateway-vpn-privileged/restore-transactions` mode `0700`. Весь `/var/lib/gateway-vpn-privileged` принадлежит root, поэтому скомпрометированный service UID не может удалить или переименовать journals через writable parent. Systemd unit конфликтует с control/broker/socket/Mihomo/dnsmasq и до file apply повторно загружает fixed boot firewall. Journal paths пересчитываются из fixed restore ID/destinations и не принимаются из HTTP; при resume journal сравнивается с ожидаемым path set. Apply helper не запускается напрямую и получает только current strict config path плюс fixed transaction root из packaged unit.

Update journals, pre-migration snapshots, complete restore points и manual rollback request находятся в раздельных root-owned `update-transactions`, `update-snapshots`, `update-restore-points` и `update-rollback` под `/var/lib/gateway-vpn-privileged`; release pointers меняются только под `/opt/gateway-vpn`. Control plane не получает filesystem path, release directory, unit name или command: broker принимает parameter-free inventory/prune и validated point ID, сам повторно выводит protected roles из pointers/journal и запускает только fixed systemd unit. Manual rollback требует session-bound CSRF, password re-authentication, destructive header и exact typed phrase до `PATH_BLOCKED`/root trigger.

Complete point сохраняет signed release identity, SQLite, config, secrets, subscriptions, TLS и Mihomo state. При projection root-only Management Fabric/WireGuard secrets остаются `root:root 0600/0700`; TLS certificate возвращается `gateway-vpn:gateway-vpn 0644`, а modes выставляются до `chown`. Partial candidates всегда удаляются. `/etc/gateway-vpn` открыт на запись только fixed `gateway-vpn-update-rollback.service` и `gateway-vpn-update-recovery.service`; обычный control plane и произвольный systemd unit не получают этой поверхности.

Recovery/finalize/rollback units запускаются через отдельный `recovery` pointer: во время stability window он указывает на старый release, после successful finalization — на новый trusted updater. Поэтому повреждённый candidate `current` не является единственной точкой восстановления, а следующую транзакцию не выполняет устаревшая версия. Update/rollback service до mutation снова загружает boot firewall; при failure management возвращается лишь после успешного recovery, который также очищает ожидаемый failed-state update/finalize/rollback units. Safety-point делает historical rollback обратимым без down-migration даже после `SIGKILL` либо reboot.

Одноразовый confirmation token хранится в SQLite только как SHA-256. Подтверждение требует фактического local destination нового LAN IP либо WireGuard management prefix; `Host`, `X-Forwarded-*` и старый destination не используются как evidence.
