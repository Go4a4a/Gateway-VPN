# Gateway VPN — модель безопасности реализации

- Любой boot начинается с `PATH_BLOCKED`; management API не открывает direct LAN path.
- Основной `gateway-vpn.service` не имеет `CAP_NET_ADMIN` и получает только `CAP_NET_RAW` для `SO_BINDTODEVICE`/`SO_MARK` служебных modem-bound DNS/HTTPS sockets. Root broker ограничен `CAP_NET_ADMIN` и `CAP_NET_RAW`, необходимыми для owned routes/nft/WireGuard и modem-bound endpoint DNS; nftables и Mihomo вынесены в отдельные units с собственными минимальными capability sets.
- Пароли хешируются Argon2id (`m=65536 KiB, t=3, p=2` по умолчанию). Session и CSRF tokens хранятся только как SHA-256 digests.
- Browser cookie: `Secure`, `HttpOnly`, `SameSite=Strict`; state-changing API требует session-bound CSRF token.
- Login failures сохраняются и получают progressive delay. Сессии отзываются в SQLite.
- Одноразовый bootstrap-пароль блокирует весь API, кроме session/password/logout, пока пользователь не задаст новый пароль. Смена собственного пароля сохраняет только текущую сессию; administrative reset и disable отзывают все сессии target user.
- Все локальные пользователи MVP являются администраторами без ролей. Username имеет консервативный ASCII-format и case-insensitive unique index; текущего/последнего enabled пользователя отключить нельзя, а удаление разрешено только после disable и отдельного confirmation header.
- API показывает только SHA-256 session ID, username и timestamps; bearer cookie, CSRF digest и client-key digest не возвращаются. Спецификация `docs/openapi.yaml` contract-tested против каждого реально зарегистрированного `/api/v1` method.
- API использует явные redacted DTO. Subscription secret refs, URLs/tokens, modem identity hash, serial и private keys не возвращаются.
- Config loader запрещает symlink, duplicate/unknown YAML fields, multi-document input и небезопасные permissions.
- TLS private key, bootstrap password и dynamic secrets создаются atomic write + fsync с mode `0600`.
- Mihomo controller доступен только на loopback и требует secret; полная subscription config не исполняется, разрешённые proxy fields проходят sanitizer.
- Content probes используют отдельный mixed listener только на numeric loopback и отдельные `probe-path-*` selectors; controlled select и HTTPS request сериализованы. Active data-path group для проверки тела не переключается.
- Policy mutation сохраняет текущий node в provider только на durable 120-секундный grace. Он не считается candidate без свежего результата новой generation; crash/restart очищает transition в `PATH_BLOCKED` до обычной convergence.
- nftables controller владеет только `table inet gateway_vpn`, выполняет `nft --check` и никогда не вызывает `flush ruleset`.
- Независимый root firewall guard имеет только `CAP_NET_ADMIN`: при потере schema generation/drop markers он сначала administratively отключает transit LAN, сохраняет root-only quarantine marker, восстанавливает только owned table в `PATH_BLOCKED` и возвращает link up после повторной проверки. Старый active TUN generation не восстанавливается без control-plane re-verification.
- Signed release требует строгие metadata, Ed25519 signature доверенным key, signer fingerprint, полный manifest и SHA-256 каждого файла; archive parser ограничивает gzip member/footer/padding, entries/path/depth/bytes и запрещает links/devices/trailing data. Staging не исполняет candidate и не меняет live state.
- Первый install не доверяет verifier из candidate archive. Отдельный `gateway-vpn-bootstrap` заранее закрепляется внешним SHA-256; generated command использует HTTPS-only `curl` с fallback на GNU `wget`, проверяет hash и лишь затем вызывает bootstrap напрямую из root-shell либо через `sudo`. Bootstrap затем независимо закрепляет raw channel manifest SHA-256, exact channel/version/source commit и Ed25519 public-key fingerprint, проверяет detached channel signature, role filename/hash/size и полный signed release tree до запуска role installer.
- Caller-supplied bootstrap URL запрещает credentials, fragment, query, literal IP и нестандартный HTTPS port. Короткоживущий signed query допускается только после HTTP redirect и только для allowlisted `objects.githubusercontent.com`/`release-assets.githubusercontent.com`; content всё равно обязан совпасть с закреплённым hash/size/signature. Redirect на иной origin или query на `github.com` отклоняется.
- Channel artifacts имеют точные role filenames (`gateway`, `vps`, `deploy`, `bootstrap`) для exact version/Linux/amd64. Trusted channel builder требует clean committed source, подписывает sorted unique role records, тут же проверяет их public key и генерирует immutable GitHub tag command; `latest`, `curl | shell` и доверие одному TLS origin не являются частью install contract.
- `gateway-vpn-deploy` до исполнения сверяется с externally pinned SHA-256, затем проверяет собственные size/hash/version/commit по signed channel. OpenSSH запускается только как fixed `/usr/bin/ssh` с отключённым user config, password, keyboard-interactive и TTY, строгим pinned `known_hosts`, bounded stdout/stderr и validated destination/port/path inputs; обе role dry-run фазы завершаются до первого apply.
- Gateway private key создаёт локальный helper от service UID, VPS private key — signed VPS installer после full preflight, admin private key — optional local deploy lifecycle. Через SSH/argv/report передаются только public keys; pending keys имеют mode `0600`, directory `0700`, переживают interruption для idempotent resume и удаляются только после atomic config write + directory fsync. Existing config принимается лишь при exact peer/endpoint contract и молча не ротируется.
- Gateway dependency provisioning также является opt-in и использует фиксированный allowlist `iproute2/nftables/wireguard-tools/kmod/procps/dnsmasq-base`, двойную APT simulation с `--no-remove --no-upgrade` и повторный full host preflight. Используется binary-only `dnsmasq-base`, а отдельный DHCP/DNS process работает как `gateway-vpn-dns:gateway-vpn` и пишет lease только в systemd-owned `/var/lib/gateway-vpn-dnsmasq` mode `0700`, вне закрытого application state root. LAN принимается только как private usable `/16../30`; bounded typed `ip -json` проверка отклоняет пересечение с WireGuard management, любым другим host address network или non-default route до application mutation.
- Gateway first-install transaction создаёт durable root-only marker до host mutation и загружает signed owned `PATH_BLOCKED` ruleset до назначения LAN/включения `net.ipv4.ip_forward`. Прежние forwarding/IPv6/link/address значения восстанавливаются owned recovery; systemd application units при active или broken marker требуют отдельный ephemeral `root:root 0600` `/run/gateway-vpn-install-authorized`, который существует только внутри живого installer и исчезает при reboot.
- Root self-health supervisor имеет только fixed signed component/action/path surface и capability set `CAP_NET_ADMIN/CAP_SYS_BOOT/CAP_DAC_READ_SEARCH`; SQLite policy читается новым query-only handle, а restart/reboot budget атомарно сохраняется и fsync-ится до действия. Любая recovery сначала применяет `PATH_BLOCKED`; external outage и resource pressure не reboot-eligible, host reboot default-off, maintenance suppresses actions. `NotifyAccess=all` ограничен собственным systemd service cgroup и нужен для heartbeats из Go runtime threads; произвольные child executables/commands отсутствуют. Control `Requires/PartOf` supervisor, а runtime directory сохраняется через restart, поэтому потеря supervisor не оставляет живой control с невидимым stale heartbeat mount.
- VPS dependency provisioning включается только явным `--install-dependencies --apply`. Installer не меняет APT sources, формирует фиксированный allowlist `iproute2/nftables/wireguard-tools/kmod/procps/python3-minimal`, до установки запускает `apt-get -s install --no-install-recommends --no-remove --no-upgrade`, запрещает любой `Remv` и любую upgrade action, после `apt-get update` повторяет simulation и не выполняет `upgrade`, `full-upgrade`, `dist-upgrade` или `autoremove`. Ошибка simulation может быть классифицирована как требующая refresh только отдельным exit code `10`; bootstrap разрешает его исключительно в read-only фазе apply-транзакции, тогда как removal/upgrade/empty plan остаются фатальными. Ubuntu 20.04 до любой managed package mutation требует уже установленные `ubuntu-advantage-tools`/`python3-minimal`, активные Pro + `esm-infra` + `esm-apps` и отсутствие pending updates; после refresh проверка повторяется до package install. После package install весь host/nft/WireGuard/port/conflict preflight выполняется заново до создания VPS private key или managed application state.
- OS packages являются состоянием хоста и намеренно не удаляются application rollback/uninstall: автоматический откат пакетов после успешного `dpkg` мог бы удалить разделяемые зависимости других сервисов. Незавершённая Gateway VPN transaction восстанавливает только owned files, sysctl, systemd, WireGuard interface/config и `inet gateway_vpn_vps` table; WireGuard keys сохраняются, если оператор отдельно не запросил purge.
- VPS install/recovery/uninstall сериализованы одним root-owned mode `0600` `flock` в `/run/lock`. Lock path создаётся с `noclobber`, symlink и чужой owner/mode отклоняются. Active transaction и orphan temp/pointer artifacts проверяются до package mutation. Recovery не архивирует active marker, пока owned nft/systemd/sysctl/filesystem cleanup и повторная проверка forwarding не завершились; при любой ошибке marker остаётся для следующего boot/manual retry.
- Root update повторно проверяет signed staging, запускает candidate offline check только после verification, мигрирует копию DB и переключает согласованную пару SQLite+`current`. Pointer-only update требует совпадения вычисленного signed `host_contract_sha256` для всего packaged systemd lifecycle; изменённые root-owned units не игнорируются, а отклоняются до mutation. Независимый `recovery` symlink остаётся на старом release весь 24-часовой health window и переводится на новый только после повторной health/DB проверки и finalization; root-owned journal/snapshots, inter-process `flock`, boot recovery и `OnFailure` resume обеспечивают fail-closed rollback. Та же версия не может обозначать другой signed artifact.
- Web/API получает root update outcome только безаргументным broker request и видит path-free DTO: versions/state/timestamps/error code. Release paths, snapshot ID, DB hash и systemd output не пересекают privilege boundary.
- Все application records проходят key/value/nested-error redaction до JSON handler и journald. Permanent debug запрещён bootstrap config: временный component-scoped debug имеет durable deadline 5 минут–24 часа, а `auth_audit` нельзя снизить ниже `info`. Gateway VPN services используют отдельный bounded journal namespace; payloads, response bodies, credentials и modem identity не являются debug data.
- Retention меняется только parameter-free broker request: root перечитывает desired policy из SQLite, пишет один фиксированный journald drop-in, проверяет fixed namespace unit и откатывает прежний файл при failure. HTTP не передаёт root ни путь, ни unit, ни retention values.
- Control plane не получает членство в широкой группе чтения system journal. Технический журнал выдаёт root broker только из namespace `gateway-vpn` через фиксированный `/usr/bin/journalctl`; allowlisted filters, page/time/cursor bounds, subprocess limit 2 MiB, broker response limit 64 KiB, session rate limit и второй redaction pass ограничивают поверхность чтения.
- Diagnostic bundle создаётся только в памяти как fixed-entry ZIP (24 MiB uncompressed/32 MiB archive) с per-file SHA-256 manifest. Parameter-free root collector запускает только фиксированные absolute `uname/ip/nft/wg/mihomo` команды, читает `/etc/os-release`, выбирает owned routing/nft state и возвращает не более 60 KiB; HTTP не передаёт command/path/interface/table или `include_secrets`. Host, event и journal данные повторно sanitizes/redacts перед ZIP, WireGuard keys/endpoint host, MAC/modem identity, subscription payloads/URLs, proxy configs/credentials и target bodies исключены.
- Endurance harness работает только на Linux, требует TLS 1.3 + explicit CA и не использует redirect или environment/argv password. Credential file обязан быть single-link mode `0600`; cookie/CSRF и password остаются только в памяти, session отзывается при exit. Samples и verified start/end diagnostics пишутся `0600` в новый `0700` directory. Smoke не может выдать endurance PASS; developer/release нельзя сократить, они требуют clean VCS-stamped harness и versioned Gateway, а release дополнительно требует explicit hardware attestation.
- Portable backup никогда не записывает plaintext ZIP на постоянный storage: `.gvpn` использует Argon2id и chunked AES-256-GCM с authenticated header, monotonically indexed chunks и обязательным authenticated final record. Restore повторно ограничивает file count/bytes, отклоняет traversal, duplicate, symlink и неизвестные paths, требует DB/config/Mihomo API secret/TLS cert+key и не сохраняет passphrase/upload после staging.
- Unprivileged staging не получает права менять live-файлы. Root apply повторно хеширует manifest tree, проверяет SQLite/config, создаёт `pre-restore` snapshot и использует только фиксированный destination set. Candidates создаются рядом с destinations, а root-owned journal/rollback paths позволяют восстановить прежний набор после partial apply или power loss.
- Restore отзывает все sessions, очищает login attempts, удаляет stale Mihomo active link и принудительно сохраняет `PATH_BLOCKED`; backup evidence никогда не считается свежей path qualification. Resume unit возвращает только management/control, а data plane появляется после обычного reconciliation.
- Bootstrap config фиксирует executable `/opt/gateway-vpn/current/libexec/mihomo` и Mihomo API secret/TLS paths внутри managed state directory. Root diagnostics также использует compile-time fixed Mihomo path; восстановленный YAML не является источником root executable/path.

Root-доступ находится вне threat model. Firewall guard защищает от сбоя/конфликтующего сервиса/административной ошибки, но не от намеренного root attacker.
## Привилегированное изменение сети

Web/API работает как `gateway-vpn` только с `CAP_NET_RAW`; capability не позволяет менять routes/nftables. Привилегированные изменения, ограниченное чтение namespaced journal, parameter-free host diagnostics, restore/update trigger и sanitized update-status read выполняет отдельный root broker через Unix socket owner `gateway-vpn`, mode `0600`; после accept дополнительно проверяется Linux `SO_PEERCRED` UID. Broker принимает strict bounded JSON, typed LAN candidate, parameter-free routing/WireGuard/logging/diagnostics/restore/update operations, bounded journal query, bootstrap tuple и protected Mihomo version IDs — не shell command, executable path, restore/update id/path/unit, destination file, произвольный interface/table, journald unit/namespace или `journalctl` argument.

`output` остаётся policy drop. Служебные DNS/HTTPS разрешаются только для UID процесса и tuples `interface × fwmark × public IPv4 × port`; Mihomo endpoint IP root получает из immutable protected payloads и разрешает отдельно через каждый `MODEM_READY`.

WireGuard private key принимается только authenticated HTTPS + CSRF update, атомарно сохраняется в `secrets/wireguard.yaml` с mode `0600` и никогда не возвращается Web API. Между control plane и root broker передаётся только пустой `sync` request: endpoint, keys, modem ID, interface, route table и fwmark root повторно получает из protected config и SQLite. nftables разрешает только текущий tuple `interface × fwmark × public endpoint IPv4 × UDP/51821`.

Transaction directory принадлежит `root:root` и имеет mode `0700`. Rollback manifest содержит только interface/CIDR/local management URLs, проверяется по schema и SHA-256. Перед privileged action broker сверяет manifest с SQLite, текущим strict config и реальными `ip -json address` данными. Snapshot/restore ограничен фиксированными Gateway VPN config, dnsmasq, persistent systemd-networkd LAN policy и owned nftables table; apply/rollback вызывает только `networkctl reload`, а старый адрес остаётся до explicit confirmation.

Restore использует отдельный root-owned `/var/lib/gateway-vpn-privileged/restore-transactions` mode `0700`. Весь `/var/lib/gateway-vpn-privileged` принадлежит root, поэтому скомпрометированный service UID не может удалить или переименовать journals через writable parent. Systemd unit конфликтует с control/broker/socket/Mihomo/dnsmasq и до file apply повторно загружает fixed boot firewall. Journal paths пересчитываются из fixed restore ID/destinations и не принимаются из HTTP; при resume journal сравнивается с ожидаемым path set. Apply helper не запускается напрямую и получает только current strict config path плюс fixed transaction root из packaged unit.

Update journals/snapshots/lock находятся соответственно в root-owned `update-transactions` и `update-snapshots` под `/var/lib/gateway-vpn-privileged`, а release pointers — только под `/opt/gateway-vpn`. Recovery/finalize units запускаются через отдельный `recovery` pointer: во время stability window он указывает на старый release, после successful finalization — на новый trusted updater. Поэтому повреждённый candidate `current` не является единственной точкой восстановления, а следующую транзакцию не выполняет устаревшая версия. Update service до mutation снова загружает boot firewall; при failure management возвращается лишь после успешного recovery, который также очищает ожидаемый failed-state update/finalize units.

Одноразовый confirmation token хранится в SQLite только как SHA-256. Подтверждение требует фактического local destination нового LAN IP либо WireGuard management prefix; `Host`, `X-Forwarded-*` и старый destination не используются как evidence.
